# BLINK Web & PWA remediation checklist

- [ ] **Server-authoritative privacy and commerce** — Store pause must be enforced inside authenticated purchase/mutation RPCs; restricted-audience media must not remain publicly readable; search fallback must exclude private and blocked accounts; message fallback must never present a partial unread-only inbox; hidden likes/comments and authored alt text must be honored in every shared renderer.
- [ ] **Feed, stories, reels and mobile creation** — Render and bind the story strip on desktop and mobile; expose visible create-story/create-post actions; provide image fallback and load/error states for reels; initialize reaction state and reconcile counts; preserve route freshness for async work; support continuation states where the existing RPC returns cursors.
- [ ] **Marketplace and seller workflows** — Make listing cards navigable to canonical detail views; use the existing authenticated order RPC for checkout/order creation; add validated filter controls and continuation affordances; make seller errors distinct from empty data and expose listing status/onboarding actions where supported.
- [ ] **Auth, search, activity and settings reliability** — Preserve sanitized return destinations through login/OAuth; remove referral handoff races; load search sections independently; use atomic mark-all-read and rollback failed per-item writes; label controls, validate trimmed inputs, and distinguish retryable errors from empty states.
- [ ] **Landing, SEO and accessibility** — Keep the public homepage independent of missing app configuration; restore `<main>` semantics; fix campus aliases and Market tour destination; preserve authored metadata/alt text; add programmatic labels, focus management, and accurate 404/download copy.
- [ ] **PWA/offline correctness** — Refresh the shell without deleting the active cache first; expose active/waiting/error service-worker status; keep private data out of caches; maintain synchronized `manus-routes.json` and manifest metadata.
- [ ] **Classic premium motion** — Apply short, reduced-motion-safe route/card/press transitions across the shared web shell; avoid decorative loops, layout shifts, and motion during data/privacy/payment confirmation.
- [ ] **Verification and delivery** — Run syntax, web parity, privacy, SEO, route-staleness, PWA and focused regression checks; document unavailable live/provider verification; push the verified implementation to `main` without force-push.
