# BLINK website update notifications (Testlab phase 6)

- Current production does NOT include the new updater or this notification feature.
- Users who installed the website APK subscribe to the public FCM topic `blink_android_website_releases`; Play Store installs unsubscribe.
- A successful **Publish latest APK** GitHub Actions run triggers a separate notification workflow on trusted `main`. It verifies the latest public release, APK metadata, SHA, tag, checksum field and artifact presence. It never sends from Testlab builds.
- Configure the GitHub Actions repository secret **FIREBASE_RELEASE_SERVICE_ACCOUNT_JSON** with a *separately scoped service account* authorized to call FCM HTTP v1 for BLINK's Firebase project. The existing `google-services.json` app config is NOT a server credential. Never commit credentials or share them in chat.
- If this secret is absent, the post-publish push workflow fails clearly, and the production release monitor opens a GitHub issue. It does not alter an already published release. A GitHub failure alert can be added for this workflow.
- FCM sends a data-only message with release version fields, not a URL. The Android client checks version codes, de-duplicates notices persistently, and opens the existing official signed-download dialog on tap. Android 13+ system notification permission is respected; disabling notifications does not disable foreground update checks.
- When the authenticated app is visible, an FCM event refreshes release metadata immediately. Every 15 minutes while the UI is STARTED, and whenever BLINK returns to foreground, BLINK rechecks the official GitHub metadata as a backup. It never requests installation without explicit user approval.
- The live APK already supports a startup update prompt linking to the website. The new download/progress/resume behavior and notifications require PR #400 + this feature's Testlab PR, main branch protection, device QA, owner authorization and a verified signed build.
- Test physical Android devices: background/terminated processes with notification permissions allowed/denied, push duplicate delivery, Play Store installs, cold-launch intents, foreground FCM delivery, Wi-Fi/cellular, failed metadata, expired release and install signer rejection. Confirm account sessions remain intact.
