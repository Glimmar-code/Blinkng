# BLINK Menu and Wallet & Coins — Testlab Integration Notes

PR #518; target: Testlab. Production publication requires separate checks and promotion.

## 2026-10-24 — Menu → dedicated Wallet & Coins page (Testlab candidate)

- **Android:** The Menu Wallet & Coins route now opens its own full-page, back-navigable screen instead of the old Earning modal. It has a server-confirmed balance card, an explicit unconfirmed/offline state, Overview/Rewards/History tabs, earned/spent filters, current daily missions with server-only claims, optional rewarded ads within existing limits, verification and BLINK Store actions. Screen adapts to compact phones and large font scaling. No fake balance, rewards or transaction rows. The ledger is the account-authenticated `get_blink_store_state` response; the UI does not write balances directly.
- **Windows:** Native Wallet & Coins screen and desktop sidebar route use `get_blink_store_state` and `get_my_daily_missions` with secure backend calls. Menu Wallet now opens this route rather than falling back to Profile. Windows supports the same balance/mission/history views, online retry and server-only mission claims. Ads remain Android-only because native Windows does not have the Android rewarded ad SDK.
- **Safety:** Coins are fictional in-app credits, not cash; cash-outs are not offered. Never fabricate historical totals or infer the full ledger from an RPC's latest-returned records. Balance fetch failures remain explicitly unconfirmed. `BlinkWalletLedgerTest` verifies missing or invalid transaction IDs do not produce fake rows and signs are preserved.
- **Verification hold:** Require current-commit Android and Windows compile/tests, real credentials on nonproduction test accounts, permissions/RLS verification, daylight/dark screenshots at 320–600dp and font sizes 100–200%, refresh/offline/claim/history navigation. No Supabase schema change or production publish.

## 2026-10-24 — Full-page BLINK Menu reference redesign (Testlab candidate)

- **Android:** Replaces the partial three-dot Menu bottom sheet with a full-screen, scrollable white/dark Menu. The approved reference's BLINK header, actual user profile card, ten colored icon rows, and five labelled bottom tabs (Home, Reels, Market, Connect, Menu) are implemented in Compose. The row numbers come from existing authenticated profile data (followers, following, points), never the screenshot's fictional community/event counts.
- **Shared:** `BlinkMenuDestination` defines one ten-route ordered contract for both clients with unit tests for unique keys, menu order, and an explicit log-out route.
- **Android actions:** Profile, Leaderboard, Earning wallet, Notifications, saved-post Profile tab, verification, privacy/security Settings, update metadata check, Help information and guarded Log Out all have real actions. Settings retains light/dark mode, notifications/calls, account switching and a role-gated Admin shortcut. Existing campus tools (edit profile, find friends, list item, Seller hub, scheduled posts, groups, market orders/wishlist and call history) remain accessible via Settings, along with conditional ad privacy choices. The website update path requires explicit user installation permission and never downloads executable app code silently.
- **Windows:** Adds Menu to the desktop sidebar and a native, responsive menu using the same labels/routes and real profile data; preserves Windows desktop navigation and logout confirmation. Windows wallet, saved items and verification resolve to the existing Profile screen, which is not yet an exact Android sub-tab equivalent. Desktop update links open the official website, not the Android APK installer.
- **Platform-specific UI exception:** Android has a five-position fixed bottom bar; Windows retains its established sidebar and window chrome. The Windows menu uses profile-level fallbacks for wallet/saved/verification until dedicated native subroutes can be verified, not fake pages.
- **Regression/verification hold:** Replacing the fifth bottom-nav Messages slot with Menu changes a primary navigation path; Messages must remain reachable from Home/other existing message shortcuts and be manually tested. Verify actual Android screens (small/regular/wide, 100/130/150/200% fonts, light/dark), saved-post hydration, update/offline states, Android back/keyboard behavior, Windows navigation and both compilers. This branch targets Testlab only. No production merge, APK release or database change has been performed.
